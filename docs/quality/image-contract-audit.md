# Image contract audit

Audited against the current `projects/orc-ds/image/*` source and focused browser tests on 2026-09-13.

`orc-image` renders the current `src` (or `fallbackSrc` after the first error), clears the primary `srcset`/`sizes` while using the fallback, resets fallback/failed state when `src`, `fallbackSrc`, `srcset`, or `sizes` changes, and emits `loaded` for a successful current image and both public error outputs (`error` and `onImageError`) once after the primary and fallback origins fail. A failed image renders the configured placeholder when present. Preview mode wraps the image in a native `type="button"` trigger; without preview, the component renders a plain image and preserves `alt=""` for decorative content.

Preview is delegated to the canonical `orc-modal`. That gives the image preview native dialog semantics, default accessible naming, first-control focus, Tab containment, focus restoration, Escape and backdrop dismissal, document scroll locking, background inertness, nested overlay ownership, and destroy cleanup. Opening is idempotent while already visible; it resets zoom to `1` and rotation to `0` only after a close and subsequent reopen. Zoom is clamped to `0.5..3` in `0.25` steps and rotation wraps in 90-degree steps. A changed main source updates an already-open preview when no separate preview source is configured. Thumbnail sizing is scoped separately from preview layout, and radius is applied to the painted thumbnail while the figure keeps overflow visible for focus outlines. The preview stylesheet keeps the toolbar in flow at narrow widths and constrains content to the viewport.

Focused evidence is in `projects/orc-ds/image/image-behavior.spec.ts` and the existing Image case in `p2-expansion.spec.ts`. It covers fallback reset and source attributes, both consumer-template error output names, plain versus preview DOM, native button click activation and idempotent repeated opening, accessible preview/control names, dynamic source updates, explicit normal/small/zero geometry for images and placeholders in preview and non-preview modes, loaded data-URL natural dimensions in the preview via `HTMLImageElement.decode()` plus an animation boundary, radius and focus-outline layout, zoom/rotation bounds and actual control clicks, viewport bounds at the runner's desktop viewport, Escape/backdrop dismissal, Tab containment, focus and scroll restoration, preview disable cleanup, destroy cleanup, and parent/nested modal ownership. The focused command passed 130 tests with runtime diagnostics.

Durable browser evidence is recorded in `docs/quality/verification/image-card-slider-batch/image-browser-qa.md`. On 2026-09-13, an ephemeral fixture importing the sealed distribution was used because the documentation `/components/image` page has no `preview=true` trigger. At the default desktop viewport, physical Tab+Enter and Tab+Space each opened one preview; Escape and a click outside the dialog closed it and restored focus to the trigger. Zoom and rotation controls remained visible, keyboard reachable, and focused after activation. Changing the source while closed and reopening visibly changed the loaded image. At 320x480, the loaded image fit the approximately 304px content width and the toolbar remained in flow; rotation left the control visible and focused. At 320x240, the preview and toolbar remained usable and Escape restored trigger focus. The browser console had no warning or error entries. This complements the focused runner's programmatic activation and fixed viewport; the exact fixture, key sequence, viewport observations, and limitations are preserved in the verification note.

Compatibility limits: `appendTo` remains accepted but does not relocate the preview because native `orc-modal` owns dialog placement and inertness; `hideTransitionOptions` remains accepted but Modal exposes one transition option. `previewImageSrc` is an independent preview origin and its failure does not switch the main image to `fallbackSrc`; if consumers need a fallback for that separate origin, it requires an explicit future contract. No new Image API was added.
