# Table contract audit

Audit and bounded follow-up of the current worktree on 2026-09-13. The source of truth is `projects/orc-ds/table/table.component.ts` and its template; `projects/orc-ds/table/table.types.ts`, the column/slot directives, the focused `table-behavior.spec.ts`, the docs table page, and the P2 `DataTableComponent` were checked alongside it. The follow-up adds pure CSV/equality helpers and focused browser coverage in the table folder.

## Canonical `orc-table` contract

`TableComponent<T>` is the canonical generic table. It accepts either `data` or the `value` compatibility input, carries `T` through selection, templates, events, and row identity, and renders a native table. It supports projected `orc-column` declarations and direct `columnsConfig`; projected columns take precedence when both are present. `TableColumnConfig` is `{ key, header, sortable?, width?, align? }`, and `align` is `left | center | right`.

The following input groups are currently supported by the source and template:

## Declared no-op or unused surface

The following declarations have no reference outside their declaration in the current `table` source/template. They should either be implemented with a tested contract or marked deprecated in the public API; they must not be described as supported behavior.

### Inputs/models

- `frozenColumns`, `frozenValue`: no frozen pane or alternate frozen data is rendered.
- `responsiveLayout`, `breakpoint`: no responsive layout mode or breakpoint logic is applied.
- `autoLayout`: no table-layout behavior is changed.
- `scrollDirection`: scrolling only uses `scrollable` and `scrollHeight`; horizontal and both-axis modes are not distinguished.
- `virtualScroll`, `virtualScrollItemSize`, `virtualScrollOptions`, `virtualScrollDelay`: no virtual viewport or item-size logic exists.
- `resizableColumns`, `reorderableColumns`: no resize/reorder handles, listeners, or state exist.
- `showInitialSortBadge`: sortable headers always render the neutral/active icon without consulting this input.
- `stateKey`, `stateStorage`: no state persistence or restoration is performed.
- `editMode`: no cell/row editing UI or lifecycle exists.
- `groupRowsBy`, `rowGroupMode`: no row grouping or grouped headers are rendered.
- `contextMenuSelection`, `contextMenuSelectionMode`, `contextMenu`: no context-menu trigger, selection handling, or menu integration exists.
- `filterDelay`: filtering is immediate; no debounce/timer uses this value.
- `metaKeySelection`: selection does not inspect modifier keys.
- `paginatorDropdownAppendTo`, `paginatorDropdownScrollHeight`: these table declarations are not forwarded to the integrated paginator.
- `sortMode`: sorting is single-column only; multiple sort state is not modeled.
- `loadingIcon`, `showLoader`: loading always renders `orc-skeleton`; neither declaration changes it.

### Outputs

- `onContextMenuSelect`
- `onColResize`
- `onColReorder`
- `onRowReorder`
- `onEditInit`, `onEditComplete`, `onEditCancel`
- `onStateSave`, `onStateRestore`

No code path emits these outputs. `onHeaderCheckboxToggle`, `onRowExpand`, `onRowCollapse`, `onPage`, `onLazyLoad`, and `sortFunction` are wired and are not in this list.

## Remaining behavior risks

These are partial or incorrect behaviors rather than unused declarations:

1. Selection intentionally preserves off-page rows in `selectedRows`, especially for remote/page-only workflows, but the retention/pruning policy is not documented. Decide and test behavior when immutable data replacement removes a selected row.
2. In remote mode, `effectiveTotalItems` trusts `totalRecords`/`totalItems`, while local mode derives totals from filtered data. The distinction is correct for consumer-owned fetching but needs explicit docs and tests for changing totals, page-size changes, and stale offsets.
3. `ngOnInit()` emits an initial remote query whenever `lazyLoadOnInit` is true, regardless of whether `effectivePaginated` is enabled. The query contract should state whether lazy loading implies paging or should be gated by pagination.
4. Rows and sortable headers are made keyboard-activatable with `tabindex`, but the native table does not expose a richer grid/row selection model. Validate screen-reader announcements for selected rows and sortable headers, especially when no `ariaLabel` or `rowAriaLabel` is supplied.
5. `exportCSV()` remains an imperative browser utility with no output or completion/error contract. Its generated header/body fields now share delimiter-aware escaping, selected-row and nested-field behavior is covered, and the object URL is revoked after the download click; SSR still returns without a download.
6. Expansion is implemented through `rowExpansionTemplate` and `expandedRows`; the focused table spec now exercises the expansion slot, `$implicit`/`row`/`index` context, multiple-row collapse events, and `rowExpandMode="single"` replacement in direct DOM contracts.

Current evidence is concentrated in `projects/orc-ds/table/table-behavior.spec.ts`, with lifecycle coverage in `all-components-lifecycle.spec.ts`, and compatibility checks in `p2-expansion.spec.ts`. The focused suite passes **36/36** and covers configured/nested columns, aliases, local and remote filtering/sorting/paging, `rowTrackBy`, eligible/page-only selection, event isolation including projected focusable custom widgets, paginator forwarding, keyboard row/header activation, key visual options, named-region fallback for whitespace-only `ariaLabel`, delimiter-aware CSV download behavior, deterministic deep selection for edge cases/cycles, and direct footer/row-expansion slot rendering. 2. P1: either implement or deprecate state persistence, frozen columns, virtual scrolling, edit/reorder/context-menu/grouping APIs, and the unused outputs. Add one contract test per retained feature before documenting it.
3. P1: implement paginator append-to/scroll-height forwarding and decide whether `filterDelay`, `metaKeySelection`, and `sortMode` are compatibility aliases or supported behavior.
4. P2: add visual/interaction coverage for responsive layout, scroll direction, auto layout, and initial sort badge if those inputs remain public.

## Bounded next implementation plan

1. CSV escaping: **completed in this batch.** Pure helpers now escape generated headers and body fields using the actual configured delimiter, including backslash/bracket/multi-character separators, quotes, CR/LF, empty values, nested fields, normal/selected rows, and no-column output. `exportHeader` remains raw by contract; browser tests assert Blob content, anchor activation, and URL cleanup including failed clicks.
2. Deep equality: **completed in this batch.** Deep selection uses canonical object-key ordering and ancestor-only cycle references with typed length-prefixed object-key/array-index path segments, so punctuation cannot make cycle paths ambiguous and shared/duplicated acyclic subobjects compare equally. No false-equality collision was reproduced because ancestor-only references remain distinguishable through their surrounding serialized structure. It has explicit tokens for missing versus undefined/null, numeric edge cases, nested arrays/objects, and Dates. Symbol-bearing records and unsupported exotic values retain identity fallback; `isRowSelected` and bulk-selection membership continue to use a Set.
3. Acceptance boundary: this batch stayed limited to CSV construction/download ownership, deep selection keys, and the nested custom-widget event guard. Persistence, virtual scrolling, and other unused APIs remain separate decisions in the ranked batches above.

## Canonical Table versus P2 DataTable

`orc-table` and `orc-data-table` are related but serve different contracts:

| Concern           | `TableComponent<T>` (`orc-table`)                                                                                                         | `DataTableComponent` (`orc-data-table`)                                                                  |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Data shape        | Generic `T[]`, `data`/`value` aliases, nested field resolution                                                                            | `Record<string, unknown>[]`; direct property lookup only                                                 |
| Columns           | Projected `orc-column` plus cell/header/footer/expansion templates, or `TableColumnConfig`                                                | Required explicit `DataTableColumn[]` (`key`, `header`, `sortable?`)                                     |
| Selection         | `selectedRows` model, single/multiple mode, row eligibility, page-only bulk scope, row-key/deep comparison                                | `selected` model plus `selection` input alias, basic row/header checkboxes, and `selectionChange` output |
| Sorting/filtering | Locale-aware nested-field sort, canonical and PrimeNG aliases, custom-sort event, configurable filter fields/locale, remote query payload | Basic direct-key sort, global `Object.values` filtering, simple sort event, optional lazy events         |
| Paging            | `pageSize`/`rows`, `first`, `currentPage`, local/remote totals, integrated full paginator and report/jump options                         | Zero-based `page`/`first`, simple previous/next controls, optional `paginator`, lazy page events         |
| Composition       | Native table with design-system checkbox/paginator/skeleton and projection directives                                                     | Inline lightweight template with no projected column/cell slots                                          |
| Advanced surface  | Expansion, CSV export, remote query/filter state, row keyboard activation                                                                 | Smaller P2 primitive with loading/empty/filter/sort/select/page basics                                   |

Direct consolidation is not justified by the current contracts alone. The generic type and projection model, one-based versus zero-based paging, event payloads, template slots, and public aliases differ, while P2 remains intentionally lightweight. A future shared implementation could reduce maintenance through internal utilities or adapters, but it should be evaluated against usage and maintenance evidence and preserve both public entry points until an explicit compatibility mapping exists.

The current docs should describe `orc-table` as the richer generic table and `orc-data-table` as the lightweight record-oriented P2 table. The public LLM guide previously called the P2 column field `label`; it now uses the source name `header`. The P2 class declares and emits `selectionChange`, so that output remains documented.

The P2 global filter now trims `filterAriaLabel`, falls back to `Filter table` when it is omitted or whitespace-only, and keeps a nonblank explicit label authoritative. The rendered-DOM regression is covered in `projects/orc-ds/p2/data-table-behavior.spec.ts`.
