# Component discoverability matrix

Updated: 2026-09-24 (Chart route added; counts below reflect the current docs catalog and matrix rows)

This matrix reconciles the 147 component declarations in [`component-inventory.md`](../component-inventory.md) against the active docs catalog, `app.routes.ts`, rendered docs templates, and route tests. “Dedicated docs route/page” means the component has its own explicit page or a dynamic catalog preview that renders the component. “Meaningful parent/structural example” means the component is rendered and exercised as part of a documented family page. “Discoverability gap” means no active catalog entry and no rendered docs/demo usage was found; it does not imply the component is low-value. Route/rendered evidence and `app-routing.spec.ts` prove discoverability and rendered-page presence; they do not prove component interaction behavior. Interaction is claimed only when a focused component spec is named in the final column.

Active catalog entries: **100**. Direct explicit/dynamic catalog routes: **99**; Stepper is the one additional catalog deep link into the Progress page. Matrix totals: **96 dedicated docs route/page**, **23 parent/structural**, **28 gaps** (147 total).

The route/test column intentionally distinguishes routing evidence from behavior evidence: `app-routing.spec.ts` checks catalog URLs and headings, while the focused specs named in the table are the only interaction claims in this matrix.

## Prioritized discoverability gaps

The highest user-facing gaps are the public interaction families with no catalog route or rendered preview:

1. **Menus, overlays, and actions:** `ConfirmDialogComponent`, `ConfirmPopupComponent`, `OverlayPanelComponent`, `OverlayComponent`, `BlockUiComponent`, `DockComponent`, `ScrollPanelComponent`, `SplitButtonComponent`, and `ScrollTopComponent` have no discoverable catalog/demo surface. These are keyboard, focus, dismissal, or positioning contracts and should be prioritized ahead of static primitives.
2. **Data and form interaction:** `SelectButtonComponent`, `ToggleButtonComponent`, `ImageCompareComponent`, `InputColorComponent`, `IconFieldComponent`, `IftaLabelComponent`, `InputGroupAddonComponent`, `InplaceComponent`, `MeterGroupComponent`, `PasswordComponent`, and `TerminalComponent` have no current rendered example. Their public behavior is difficult to assess from generic API metadata alone.
3. **Supporting P2 and layout families:** `ChartComponent`, `OrganizationChartComponent`, `KnobComponent`, `PanelComponent`, `FieldsetComponent`, `FloatLabelComponent`, `FluidComponent`, `OverlayBadgeComponent`, `MessagesComponent`, and `ProgressSpinnerComponent` remain absent from the catalog/demo surface. Add examples according to interaction value and parent composition, rather than inferring low value from the gap.

The matrix preserves the current `/components/tree`, `/components/tree-table`, and `/components/data-view` previews and their route regression through `app-routing.spec.ts`; DataView page-level interaction evidence is recorded in [`data-view-docs-batch/gate-summary.md`](data-view-docs-batch/gate-summary.md).
