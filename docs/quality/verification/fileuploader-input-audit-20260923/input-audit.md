## Compatibility and behavior boundary

`writeValue`, `registerOnChange`, `registerOnTouched`, and `setDisabledState` remain the CVA boundary; they are not among the 44 signal inputs. Existing behavior tests cover accepting values, notifying change/touch on accepted selection, and releasing uploader-owned previews on value replacement. The public exports and selectors (`orc-file-uploader`, `orc-file-upload`) were not modified.

The stylesheets were not changed, so existing responsive sizing and scroll behavior remain intact. The focused test file covers the interaction paths affected by the new assertions; it does not constitute a visual breakpoint screenshot audit.

## Remaining risks

No concrete defect requiring an implementation change was found. Test coverage is behavior-level and browser-DOM based; there is no screenshot verification across viewport breakpoints. HTTP progress/error/cancel coverage exists, while real network/server interoperability is outside this local audit. File-size and type validation are client-side checks and do not replace server validation.
