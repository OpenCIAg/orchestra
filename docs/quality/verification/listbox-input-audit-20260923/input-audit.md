## Findings and changes

The declared filter match mode union exposed `in`, `lt`, `lte`, `gt`, and `gte`, but runtime filtering fell back to substring matching. Those modes now work for array-valued fields and numeric fields. The previous `notEquals` implementation used an any-field comparison, so a row containing one equal field could still match due to a second unequal field; it now excludes a row when any searchable field equals the query. Invalid numeric queries and nonnumeric/empty field values do not match numeric comparisons. The same focused run also caught a `dataKey` identity defect: enabling object-key comparison made distinct primitive values compare equal because both primitive `.id` reads were `undefined`; keyed equality is now applied only when both values are objects, with primitives retaining strict equality.

Visible `label` text previously had no programmatic relationship to the listbox. It now receives a stable derived id, and the list uses that id as its accessible name unless the caller supplies an explicit `ariaLabel` or external `ariaLabelledBy`.

`ListboxComponent` remains exported through the legacy form-components barrel; the focused spec asserts that both import paths resolve to the same class constructor.

## Verification and limits

Focused Karma verification passed **12/12** tests in Chrome Headless, including the existing import-identity assertion. `ng build orc-ds` also passed after the final changes. Full logs are saved as [`focused-tests.log`](./focused-tests.log) and [`build-lib.log`](./build-lib.log).

No unverified input remains. The deprecated no-op list is a compatibility decision, not an endorsement of those unsupported behaviors. No grouping, virtualization, lazy loading, select-all UI, checkbox/checkmark rows, striped/highlight modes, or status announcements are claimed.
