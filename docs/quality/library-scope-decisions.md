# Library scope and redundancy decisions

A short implementation is not automatically useless. A component earns its place by providing consistent semantics, interaction, accessibility, layout or compatibility. Public import paths are not separate components, and removing an alias alone does not improve rendered performance.

The latest integrated gate passes **1464/1464** under both seeds, **36/36** Chromium/Firefox/WebKit Playwright checks, and docs tests (**82/82**); library/docs/template builds, compatibility, current/minimum package/type/Sass consumers, SSR (**147/147**), themes, inventory, integrity, formatting, and diff checks also pass. See the [latest enterprise component gate](verification/enterprise-component-followup-20260924/gate-summary.md). No whole component can be called useless from repository evidence alone. `OverlayComponent` retains a live visibility contract despite deprecated compatibility inputs; `TooltipComponent`, one-line aliases, and import aliases are compatibility-window/major-release review candidates pending external usage and semver review. Chart's four legacy status-only types are retained because removing them from its exported union would be breaking. The earlier **1377/1377**, **1337/1337**, **1329/1329**, **1295/1295**, **1225/1225** Chart/Portal, and **1221/1221** Tree/TagsInput/spacing checkpoints remain historical evidence.

The earlier form-control extraction passed **1243/1243** and preserved class identity through the Calendar, DateInput, Combobox, and Listbox legacy exports; see the [historical form-control separation gate](verification/calendar-separation-followup-20260923/gate-summary.md). The historical **1295/1295** follow-up extracted TagsInput with identity-preserving exports, repaired MultiSelect filter/selection-limit behavior and TreeSelect blur/disabled timing, fixed Tooltip content wrapping, and classified TreeSelect, DataTable, Select, Table, TreeTable, NumberInput, and Modal. NumberInput has 55/55 tested inputs, TreeTable has 48 tested plus 28 deprecated no-ops, and Modal has 38 tested plus 11 deprecated no-ops across 49 inputs/models. See the [1295/1295 gate](verification/form-controls-next-followup-20260923/gate-summary.md) and the component-specific input audits for Select: verification/select-input-followup-20260923/gate-summary.md (archived, see release CI artifacts), TreeTable: verification/tree-table-input-audit-20260923/input-audit.md (archived, see release CI artifacts), NumberInput: verification/number-input-audit-20260923/input-audit.md (archived, see release CI artifacts), and Modal: verification/modal-input-audit-20260923/report.md (archived, see release CI artifacts).

## Separation-of-concerns debt

Several P2 implementation modules still contain unrelated component classes, large inline templates/styles, and mixed input/state/DOM logic. `CalendarComponent`, `DateInputComponent`, `ComboboxComponent`, `ListboxComponent`, `TagsInputComponent`, `MultiSelectComponent`, `TreeSelectComponent`, and `DataTableComponent` now live in focused modules, with ISO date validation in `p2-date-utils.ts`; `GalleriaComponent` and `GalleryImage` have been extracted to `p2-galleria-component.ts`; `OrderListComponent` and `PickListComponent` have separate modules; `TerminalComponent` and `ImageCompareComponent` have focused modules; `CascadeSelectComponent` lives in `p2-cascade-select-component.ts`; `TreeComponent` and `TreeTableComponent` now live in focused modules with readable Tree template markup; `SpeedDialComponent` lives in `p2-speed-dial-component.ts`; and `BlockUiComponent` plus `BlockUiTarget` now live in `p2-block-ui-component.ts`. `ConfirmationService`, `ConfirmationRequest`, and `ConfirmDialogComponent` now live in `p2-confirm-dialog-component.ts`. Their previous direct import paths remain compatibility barrels. The historical P2 module/input gate, including Splitter, Portal, DataTable, ContextMenu, PickList focus, and OrderList numeric-value handling, passed 1337/1337 tests under both seeds, package/type/Sass consumer checks, docs tests/build, and SSR; the current integrated result is in the enterprise component gate above. Existing compatibility barrels and secondary entry paths remain intact.
